## TBO on the DP cases (conc 8/16/32) — 2026-07-01

DSV4 non-EP DP two-batch-overlap A/B on the same best DP config
(`tp8dp8 CHUNK=16384 SWA=0.1 MEM=0.80 DELAYER=off`). TBO enabled via
`SGL_EXTRA_ARGS="--enable-two-batch-overlap"` + `GPU_MAX_HW_QUEUES=5` (no
`SGLANG_ENABLE_DP_TBO` env — it was removed; DP TBO auto-enables from
`--enable-dp-attention` + `--enable-two-batch-overlap`). Same client
(NP_MULT=4 WARM_MULT=1, `70000:300`). Both sides stable (no HSA crash), with
the record_stream→event+ref combine fix in place.

| conc | baseline tok/s | +TBO tok/s | throughput | baseline TTFT (ms) | +TBO TTFT (ms) | TTFT |
|---:|---:|---:|---:|---:|---:|---:|
| 8  | 29,126 | 30,661 | **+5.3%**  | 13,002 | 11,689 | −10.1% |

- **TBO's win grows with concurrency (+5.3% → +11.7%)** and is **larger than the
  8k/1k case (+8.7% @conc256)** because 70k/300 is far more prefill-dominated —
  TBO overlaps the DP gather/combine comm with the other ubatch's attn+MoE
  compute, so a bigger prefill fraction = more overlap.
- TTFT drops 10–13% (prefill latency directly benefits).
- baseline numbers match the best-of table above (29.2k/36.8k/42.1k), confirming
  the A/B baseline is the tuned config.
- Launch (TBO): `GPU_MAX_HW_QUEUES=5 SGL_EXTRA_ARGS="--enable-two-batch-overlap"
  MODE=tp8dp8 CHUNK=16384 SWA=0.1 MEM=0.80 DELAYER=off bash run_sgl_dsv4_70k.sh`

## Gotchas to remember
- DP MoE runs on the GATHERED global batch (per-rank chunk × dp) → mem-fraction
  must be ≤ 0.80 or `fused_moe` stage2 OOMs.
- DSV4 uses `DSV4PoolConfigurator`: swa sub-pool = full × swa_full_tokens_ratio;
  it binds TP8 at conc=32 (swa usage→1.0). conc32×70k is at the single-node mem
  ceiling in TP8.
- prefill-delayer is regime-dependent: OFF for long-context prefill-dominated
  low-conc; ON for 8k/1k high-conc decode-heavy.
- Server kill recipe (frees all VRAM): kill rocm-smi --showpids + pkill -9 -f
  sglang; wait ~15–20s; confirm with rocm-smi.
