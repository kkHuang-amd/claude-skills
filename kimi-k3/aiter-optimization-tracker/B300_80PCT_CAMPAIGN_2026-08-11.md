## Experiment 1: multi-token BFA group64

The existing B1 group64 projection already combines:

```text
wide q/k/v/g + beta + f_a
```

The prototype extended its token grid to B2/B4 and graph warmup. Correctness
covered B1/B2/B4; 13 focused tests passed.

```text
                   total tok/s  output tok/s  TPOT ms
baseline                969.04       107.67     17.66
multi-token BFA         992.59       110.29     17.22
delta                    +2.43%       +2.43%    -0.44
```

The individual 0.3 ms gate passed.

## Experiment 2: multi-token FP8 preroute

The B1 tri-projection was extended to B2/B4:

```text
FP8 routed-down + FP8 shared gate/up + BF16 router
```

Multi-token tri-projection correctness passed; eight focused tests passed.

```text
                   total tok/s  output tok/s  TPOT ms
BFA only                992.59       110.29     17.22
+ preroute             1017.38       113.04     16.78
incremental              +2.50%       +2.49%    -0.44
vs baseline              +4.99%       +4.99%    -0.88
```

This path inherits the existing preroute graph/capacity tradeoff and remained
opt-in.

## Experiment 3: multi-token fused shared-down

The fused SiTU + row-scaled-FP8 shared-down kernel was extended to B2/B4,
removing the standalone SiTU/shared-down boundary for covered batches.
Correctness was included in the eight focused preroute tests.

```text
                   total tok/s  output tok/s  TPOT ms
+ preroute             1017.38       113.04     16.78
+ shared-down          1053.03       117.00     16.18
incremental              +3.50%       +3.50%    -0.60
vs baseline              +8.67%       +8.67%    -1.48
```

This was the strongest cumulative result, but it missed the Phase-A gate:

```text
required: total >=1080 tok/s and TPOT <=15.8 ms
observed: total  1053 tok/s and TPOT  16.18 ms
```

It also reached only 65.9% of B300 single-stream total throughput, versus
60.6% at baseline.

## Experiment 4: multi-token latent tail

The RMSNorm + FP8 up-projection + shared-add tail was extended to B2/B4.
Nine focused tests passed.

```text
                   total tok/s  output tok/s  TPOT ms
+ shared-down          1053.03       117.00     16.18
+ latent tail          1056.71       117.41     16.12
incremental              +0.35%       +0.35%    -0.06
```

The incremental result failed the 0.15/0.3 ms item gate.

## Decision

Phase A did not meet its cumulative stop gate. The campaign therefore did not
start the higher-risk route-major stage1 ABI, copy/attention/KDA boundary work,
five-round production gate, or C4-C32 expansion.

All experimental source changes were removed. No commit was created.

This result does not show that 80% is fundamentally impossible. It shows that
extending the existing B1 FP8 fusion family to B2/B4 closes only about 1.5 ms of
the required 4.42 ms and carries graph/capacity costs. A future attempt needs a
larger structural boundary removal before reopening the campaign.

## Follow-up: B2 solution retained

The strongest subset was subsequently restored and revalidated with a
contemporaneous baseline. B2 improved total throughput by 8.70%. B4 regressed
when covered, so the final implementation only dispatches M=2 and leaves C4
flat.

The source is now retained behind `SGLANG_K3_AITER_B2_FUSIONS=1`; the earlier
"all source removed" statement above describes the initial stop point, not the
final workspace state.
